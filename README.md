# DocuMask-Local

Полностью офлайн необратимое обезличивание (деидентификация) документов:
паспорта, договоры, сканы. Без облака, без внешних API — работает целиком
внутри корпоративного контура. Сделано под комплаенс 152-ФЗ / GDPR, а не просто
ради удобства.

> Суть продукта: пропущенный паспорт = штраф. Архитектура спроектирована так,
> чтобы *пропустить* ПДн было трудно, а *доказать*, что ты ничего не пропустил,
> можно автоматически.

---

## 4 принципа, зашитые в архитектуру

1. **Recall-first (полнота важнее точности).** Три перекрывающихся детектора
   (RegEx + NER + YOLO-зоны) объединяются. Мы намеренно перемазываем лишнее.
   Точность (precision) — это про UX, полнота (recall) — это про закон.
2. **Необратимость по построению.** Рендер → маскирование пикселей → пересборка
   PDF только из картинок. Исходный текстовый слой физически не выживает.
   Никаких «чёрный прямоугольник поверх текста».
3. **Не проверено — значит не сделано.** Каждый результат ре-OCR'ится. Если
   паттерн ПДн всё ещё извлекается → джоб ПАДАЕТ (строгий режим). Гарантия
   *измеряется*, а не декларируется.
4. **Human-in-the-loop.** Полный автомат на паспортах — юридическая ловушка. UI
   даёт шаг просмотра/правки перед финальным «сплющиванием».

## Структура проекта

```
documask-local/
├── documask/
│   ├── config.py          # единый источник правды (DPI, пороги, пути)
│   ├── schemas.py          # Box / PageResult / Verification* / JobStatus — общий словарь
│   ├── pipeline.py         # оркестратор (render→detect→merge→mask→assemble→VERIFY)
│   ├── jobs.py             # персистентная очередь на SQLite (НЕ BackgroundTasks)
│   ├── audit.py            # журнал без ПДн (кто/когда/какой тип, никогда — значения)
│   ├── worker.py           # опрашивает очередь, гоняет пайплайн
│   ├── api.py              # FastAPI: загрузка → job_id → опрос статуса → скачивание
│   ├── ui.py               # Streamlit: drag-drop, тумблеры, шаг просмотра
│   └── core/
│       ├── pdf_io.py        # рендер 300 DPI + сборка «сплющенного» PDF
│       ├── preprocess.py    # deskew/denoise (твоё УТП: фото-сканы с телефона)
│       ├── detectors.py     # OCR + RegEx + NER + YOLO(ONNX)
│       ├── merge.py         # объединение пересекающихся боксов + паддинг
│       ├── masking.py       # деструктивная заливка/блюр в пиксельном пространстве
│       └── verifier.py      # ре-OCR результата, падение при остаточных ПДн
├── tests/
│   └── test_recall.py       # главный файл: харнесс recall + сквозной тест на утечку
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
└── .env.example
```

Каждый `.py` — это каркас: настоящие импорты, сигнатуры, docstring'и и
пронумерованные маркеры `ШАГ` в теле. Тело функций ты пишешь сам, идя по маркерам.

## Установка

Установщик Windows использует Python 3.11 через `py -3.11`, создаёт отдельное
окружение `.venv` и ставит зависимости только туда. Системный Python не меняется.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env        # поправь при необходимости
```

Или запусти `install.ps1 -NoServices`. Для регистрации API и worker как
Windows-сервисов запусти `install.ps1` от имени администратора.

### Быстрый запуск

```powershell
run_documask.bat
```

Для разработки доступны `start.bat`, `app.py` и `python -m documask.desktop`.
Клиентский `DocuMask.exe` собирается отдельно через `build_exe.bat`; модели и
лицензии не коммитятся в репозиторий.

Запуск воркера, API и UI в трёх терминалах:

```powershell
python -m documask.worker          # потребитель очереди
uvicorn documask.api:app --reload  # API на :8000
streamlit run documask/ui.py       # UI на :8501
```

## Роадмап на 14 дней (порядок recall-first)

Порядок намеренно НЕ «сначала лёгкое». Сначала атакуешь главный риск (recall +
верификация), а уже потом тратишь время на UI/Docker, которые ты и так умеешь.

### Фаза 0 — Снять риск (Дни 1–4) ← фаза «пан или пропал»

- **День 1 — Контракты + I/O.** Реализуй `schemas.Box` (`__post_init__`, `iou`,
  `padded`) и `core/pdf_io.py` (`render_pdf`, `assemble_pdf`). Проверка
  вменяемости: отрендерь PDF, собери обратно, убедись, что в результате НЕТ
  выделяемого текста (открой в просмотрщике, попробуй выделить). Это свойство —
  весь продукт.
- **День 2 — Собрать набор фикстур.** Создай `tests/fixtures/` с 30–50
  размеченными РФ-документами (паспорт, СНИЛС, ИНН, договор, фото с ID).
  Синтетика для старта подойдёт. Без ground truth ты летишь вслепую по recall.
- **День 3 — Текстовая детекция.** Реализуй `ocr_words` (PaddleOCR) +
  `RegexDetector` с РФ-паттернами в `detectors.py`. Прогони харнесс recall на
  текстовых ПДн.
- **День 4 — Спайк верификации.** Реализуй `verify_output`. Замаскируй фикстуру
  грубо, прогони verify, убедись что он ловит намеренно пропущенный номер.
  **Если верификация работает — продукт реален.** Замерь базовый recall.

> Гейт: если на День 4 recall по структурным ПДн (паспорт/СНИЛС/ИНН) не ≥ ~0.95,
> остановись и чини детекцию, прежде чем строить что-либо ещё. Всё, что ниже по
> пайплайну, бессмысленно, если детекция течёт.

### Фаза 1 — Визуальный слой (Дни 5–8)

- **День 5 — Датасет печатей/подписей.** Стяни наборы `signature-detection` /
  `stamp-detection` с Roboflow. Закладывай 800–1500 изображений на реальный
  recall, а не оптимистичные 200–300. Добавь класс лицо/паспорт-зона для
  fallback.
- **День 6–7 — Обучить + экспорт YOLOv8n → ONNX.** Реализуй `YoloDetector`
  (`_preprocess` / `_postprocess`, маппинг класс→`PiiKind`). Проверь, что ONNX
  крутится на CPU через onnxruntime (без torch в проде).
- **День 8 — NER + merge.** Реализуй `NerDetector` (Natasha) и `merge.combine`
  (объединение пересечений + паддинг). Перепрогони харнесс recall со ВСЕМИ
  детекторами. Здесь fallback «ФИО как зона» должен дотолкать recall к цели.

### Фаза 2 — Сквозной пайплайн (Дни 9–11)

- **День 9 — Маскирование + препроцесс.** Реализуй `apply_masks` (fill/blur) и
  `preprocess.deskew`. Свяжи `pipeline.run_pipeline` от начала до конца.
- **День 10 — Сквозная верификация.** Добейся прохождения
  `test_no_known_leak_patterns_after_masking`: полный пайплайн → verifier находит
  НОЛЬ утечек. Этот тест подтверждает маркетинговое обещание.
- **День 11 — Очередь + аудит.** Реализуй `jobs.py` (SQLite-очередь,
  `claim_next`, `requeue_stuck`) и `audit.py`. Подключи `worker.py` к потреблению
  джобов.

### Фаза 3 — Интерфейсы + поставка (Дни 12–14)

- **День 12 — API.** Реализуй `api.py`: `POST /jobs` (загрузка→job_id),
  `GET /jobs/{id}` (статус), `GET /jobs/{id}/result` (скачивание). **Добавь
  авторизацию** — даже on-prem неаутентифицированный эндпоинт с ПДн = риск.
  Отметь это клиенту.
- **День 13 — UI + ручной просмотр.** Реализуй `ui.py`: drag-drop, тумблеры по
  типам ПДн и шаг просмотра/правки (`ReviewHook`) перед финальным сжатием.
  Batch-режим (папка).
- **День 14 — Docker + отчёт аудита.** Доделай `Dockerfile` /
  `docker-compose.yml`, хук лицензии по Hardware-ID и одностраничный отчёт
  «0 утечек» для комплаенс-офицера. Прогони весь контейнер на чистой машине.

## Что намеренно НЕ входит в MVP

- **Redis/Celery.** SQLite-очередь избавляет от поставки лишней инфры в on-prem
  коробку. Замена локализована (все общаются через `jobs.py`, а не сырой SQL),
  если позже понадобится пропускная способность.
- **Требование GPU.** Работает только на CPU через ONNX + Paddle CPU-сборку.
  GPU — опционально.
- **Хоть что-то облачное.** By design. Никаких исходящих вызовов. Это и есть
  продукт.

## Юридическая ремарка (прочти перед продажей)

Этот инструмент — *помощник* по обезличиванию. В EULA финальная ответственность
за проверку должна лежать на операторе, с рекомендацией ручного просмотра.
Verifier + журнал аудита — это твой доказательный след, а не передача
ответственности. Не продавай «100% гарантия» без включённого шага
human-in-the-loop.
